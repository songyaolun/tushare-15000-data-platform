# 架构说明

平台以接口总账为入口，将公开文档中的权益事实、采集政策、运行证据和实际消费关联起来。15,000 积分表示权限与频率档位，平台按业务需要采集，不制造请求。

```mermaid
flowchart LR
    D[公开文档与离线快照] --> C[接口总账与政策]
    C --> P[任务计划]
    P --> R[传输与原始层]
    R --> Q[标准化与质量门禁]
    Q --> S[标准版本与检查点事务]
    S --> I[时点信息产品]
    I --> V[覆盖率与债务]
```

## 模块职责

| 模块 | 职责 |
| --- | --- |
| catalog、models、data/policies.json | 接口发现、证据合并、分类与声明式政策 |
| client、raw | HTTPS、连接复用、限速、重试、分页及原始响应校验 |
| access、credentials、survey | 账户实测放行、既有凭据读取、可恢复的公共接口扫描及研究样本 |
| bars | 通过底层 HTTPS 接口组合行情、固定锚点复权与均线 |
| standard、quality、pit | 日期与单位转换、质量规则、可见时点与固定锚点复权 |
| store、ingest | DuckDB 控制面、任务规划、事务提交与中断恢复 |
| coverage、products、cli | 分母可复核的覆盖指标、产品、命令行操作 |
| product_foundation | 独立产品基础模型、显式适配、统计组件、只读参考消费和产品库 |
| equity_research | P01/P03/P04/P06/P07/P13 默认引擎、P03统一右侧结构排名、共享股票适配、研究 CLI、产品存储和完整校验 |
| strategy_discovery.feature_experiments、frozen_feature_combination | 按 SHA 固定候选特征块，枚举单组与组合，构造分层置换对照及数值树便携导出；不负责采集或交易规则 |
| regime_research.execution_market | 只读核验冻结证券日的分钟及开盘竞价证据；复用RawStore信封和ReferenceContract，输出覆盖与拒绝原因，不联网或修改交易账本 |
| progress | 独立JSON阶段、耗时、失败与心跳输出；不接触模型、候选、账户数值或凭据 |
| strategy_discovery.portable_validation | 确定性代表/有限值极端/NaN边界行选取和有界便携一致性检查；完整检查必须显式选择，原生分数不被替换 |
| strategy_discovery.feature_importance | 冻结树的节点增益、分裂次数、同日排名和行业约束名单诊断；不拟合、不回放账户，增益份额不解释为线性权重 |
| strategy_discovery.permutation_audit | 按日记录置换中的单行缺失层、全空行、不可变行和实际变值行，防止将无法置换误报为不敏感 |
| strategy_discovery.native_prediction | 对逐行独立的原生模型按显式批大小预测并保持原行序；拒绝非法分数，采用批大小前须核对冻结原生结果 |

研究入口 `scripts/research/train_feature_case.py` 从预先登记的清单读取同轴特征，沿用原标签、日权重与 HGB 参数。每个 case 保存输入和源码指纹、模型、全候选预测与便携推理一致性证据，再由 `scripts/replay_return80_ablation.py` 执行固定本金、证券范围和成本的账户回放。新增数据源在各自特征模块完成日期、单位、窗口及版本审计，未知保留 NaN。实验不会自动修改 StockOps 生产模型或交易规则；验收见 `docs/e2e/return80-feature-combinations-20261019.md`。

训练入口默认启用sklearn官方迭代日志，并分别报告fit、native_predict、portable_verify阶段；
`--training-verbose 0`关闭框架逐轮输出，`--quiet-progress`关闭新增细节日志。
回放入口在加载、每个成本账户模拟与核账外包裹相同阶段记录。长阶段每30秒输出心跳，
不修改运算顺序或分块推理。`scripts/research/watch_return80_progress.py`只读既有进程
CPU累计时间和成功落盘的账户/模块/SQL窗口，转发新增日志；它不会重启任务或估算百分比。
旧任务采用旧源码快照，新日志执行版本另行冻结，完整性校验分别核对两者。

研究训练默认`--portable-validation bounded`，最多512个原轴代表/边界样本；
`--portable-validation full`才逐行检查完整候选轴。原生预测后先写`model.pickle`、
`candidate-prediction.npy`、`scores.npy`，全部写完并哈希后原子发布`native-checkpoint.json`。
后续便携检查失败不会删除这批原生结果，检查点只声明native_ready，不声明portable认证。
审计明确记录检查模式、行数、行索引SHA和full_portable_verified；bounded模式不写
“全量误差为0”。输入/账本/交易规则核验不因导出检查范围缩小而取消。

`scripts/research/analyze_feature_importance.py` 接收 SHA 固定的模型、候选轴、特征块和
成熟标签，只对预登记的完整候选日做原生预测及同日缺失掩码分层置换。单列和联合分组
分别记录，逐项输出真实完成数并落盘。每个模型的基准预测须与原生冻结分数逐元素相同。
并行任务使用独立协议和输出目录；恢复时只复用指纹固定、键唯一且属于当前协议的记录，
不重算已完成置换。原执行源码、协议和中断记录保留，恢复版本另行冻结。名单先按稳定
分数排序选同行业最多一只，再应用共同资格，不补位；最新未成熟日期只比较行为。
验收见 `docs/e2e/annual250-feature-importance-20261020.md`。
`groups_only` 将后续大样本复核限制在预登记的少数组；`audit_by_day` 追加缺失分层
诊断。长预测使用既有 `progress_phase` 输出真实阶段及心跳，不改变原生模型运算。
`prediction_chunk_rows` 限定原生模型单批行数，默认整批；它不调用便携推理。

`audit_execution_market`接收调用方冻结的`ExecutionDemand`、`ExecutionArtifact`及接口契约，
核验原始字节、请求／响应哈希、证券日、字段、量价、分钟时间覆盖和重复冲突。
调用方必须提供状态证据字节及其哈希；`source_reference`指向独立日历、上市及停牌依据，
本模块验证声明一致性，不认证引用来源本身。正常交易日须取得两接口证据；有依据的停牌、
未上市和非交易日单列，不能代替市场覆盖，且不得与模拟成交矛盾。
执行单位、上海时区及精确时间语义未知时拒绝。即使数据通过，容量、历史PIT和当前权限
认证仍为false。该模块与账户回放无调用关系，验收见`docs/e2e/annual250-evidence-validator-20261020.md`。

## 存储边界

DuckDB 使用单线程、512 MiB 内存限制，适合个人账户的单写者工作负载。控制表保存接口、任务、探活、检查点、质量结果和消费清单。标准层按接口、业务键、版本和证据来源隔离，保留所有观察版本，包含 A→B→A 的历史修订。

`products.duckdb` 与控制库、`reference.duckdb` 分离。`product` schema 保存 11 张共享产品表，`research` schema 保存六个股票业务产品的结果、特征、贡献、证据、门禁、信号、血缘及运行摘要，其中 P03 为统一右侧候选榜。参考输入只读，产品记录按模型、版本、单位和时点验证。详见[产品加工基础层](产品加工基础层.md)与[股票研究闭环](股票研究闭环.md)。

原始 JSON 按内容哈希保存。请求标识仅包含接口名与无凭据参数。成功响应先原子落盘、同步并读回校验，再解析字段。分页、标准化或质量检查失败时，保留已有原始文件，标准数据和水位不提交。标准层和检查点在同一事务中提交；已登记计划中的早期失败分片会阻止水位越过缺口。

已提交任务重复执行不会请求数据。新的回看计划具有新的观察时点，可获取迟到记录与修订。原始文件和数据库不组成跨资源事务：崩溃可能留下没有对应检查点的原始文件，这是可恢复的预期状态。不会根据孤立原始文件推断采集成功。

## 时间语义

报告期、公告日期、实际披露日期、生效时间和系统观察时间各自保存。财务记录保留 report_type、update_flag 和源版本。as-of 同时检查业务可见时间和 observed_at；后观察到的旧公告修订不会泄漏给更早的查询。

没有可信披露时点的快照只允许在本系统观察之后使用。月、季、年保持报告期间含义，不伪造发布日期。日粒度公告按 UTC 日末可见，属于保守边界；若需要国内市场盘中回测，应补充精确披露时间与明确交易时区。

上述 UTC 日末规则属于旧 `pit.as_of`。新产品基础层对日期级公告使用显式来源市场时区的次日零点，并区分观察后可见与已经生效；历史 PIT 资格仍为 false，不启用历史交易结论。

未复权价格和复权因子分别保存。qfq 和 hfq 都要求调用方显式提供固定锚点，计算为价格乘当日因子再除以锚点因子。平台不会只保留随时间变化的前复权序列。

## 覆盖率口径

登记覆盖率以全部发现记录为分母。探活、采集、消费、新鲜度和回填按各自运行证据统计，输出分子、分母；没有计划的历史回填率为 null。消费要求真正生成包含数据的产物，仅配置一个产品名不会计作已消费。

离线 fixture 与 live 分开记录。离线全部通过也不能证明真实账户权限。官方文档冲突、未归类接口、缺少更新时间、质量参考数据缺失、尚未采集或消费均保留为债务。历史回填指标只覆盖已登记计划范围，不代表已覆盖提供方全部历史。

文档分类与账户实测独立存储。公共只读接口不因文档待复核、权限未知、独立权限或停更标签而停止探测；同账户、同政策的最新成功证据可以放行真实采集。质量门禁继续阻止不完整标准数据提交。扫描样本保留原始数据和质量诊断，不计作完整历史采集。数据库按公开账户别名隔离，使用者更换实际账户时必须同时更换别名及数据库。

## Return80 跨机器研究入口

`return80-research`进入`return80_research.cli`，数据存储与行轴验证位于`dataset`，采集
编排位于`collection`并复用`client.Client/RawStore`，日频特征构建位于`features`。
`strategy_discovery`统一保存筹码、预告、公告反应及财务质量/估值纯计算。
回放入口`return80_research.replay`调用原`simulate_candidate_allocation`和账本核验；
`strategy_discovery.replay_inputs`加载哈希清单、行情面板与公司行动，不执行数据目录
里的Python。兼容脚本`scripts/replay_return80_ablation.py`仅转发库入口。

研究目录由数据集dataset.json、新特征block.json、采集collection.json与回放replay.json
分别声明。路径相对于各自目录，SHA与股票/日期轴均在消费前核对；缺数据保留NaN。
正式产品仍由StockOps App安装选定模型并调用，不反向依赖本研究仓，不改变生产交易规则。
