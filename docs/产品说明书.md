# 产品说明书

这份说明书面向产品使用者。它回答三个问题：平台现在有哪些研究产品，每个产品把数据加工成了什么，以及拿到结果后应该怎样使用。

平台提供十三个研究产品。P03统一筛选回调后出现转强证据、入场距离受控的右侧交易候选，不再划分短期、中期和长期排名。其他产品覆盖市场环境、主题、财务、预期、治理、资金及跨资产研究。

所有产品都输出数据，不依赖前端。结果写入独立的 `products.duckdb`，也可以通过 CLI 读取为 JSONL。产品只使用通过实体、时间、单位和质量门禁的来源记录；缺少必要证据时会留下 `unknown` 和原因码，不会补零或猜测。

## 一份产品结果包含什么

每条结果都使用同一套公共结构。

| 字段 | 含义 | 使用建议 |
| --- | --- | --- |
| `product_id` | 产品及版本 | 查询和血缘关联都以它为准 |
| `entity_id` | 市场、证券、基金、合约、主题或组合身份 | 不要用名称替代实体标识 |
| `analysis_as_of` | 研究截止时点 | 只能解释这个时点以前可见的信息 |
| `state` | `ready`、`annotated`、`incomplete`、`blocked` 或 `unsupported` | 先读状态，再读数值 |
| `score` | 产品内综合分 | 为空时不能自行补零；不同产品的分数不能直接横比 |
| `rank`、`peer_count` | 同口径同行池中的名次和样本数 | 同时核对 `feature_profile` 和同行层级 |
| `metrics` | 原始或衍生业务指标 | 每项都有单位、状态、原因和证据 |
| `contributions` | 因子权重、变换和评分贡献 | 用于解释总分，不等于收益归因 |
| `quality_gates` | true／false／unknown 门禁 | 硬门禁失败不能被高分抵消 |
| `evidence_refs` | 来源接口、记录、字段和观察时间 | 用于回查参考库原始证据 |
| `parent_result_ids` | 上游产品结果 | 用于复算产品依赖和组合血缘 |
| `gate_codes` | 数据或业务缺口原因码 | 排查空分数和受阻结果的第一入口 |
| `decision_allowed` | 能否进入后续人工研究流程 | 统一P03固定为 `false`，供人工复核 |
| `historical_pit_certified` | 是否完成历史时点认证 | 当前所有产品均为 `false` |

`annotated` 表示结果可供当前观察研究，但仍带限制。`incomplete` 表示必要数据、口径或门禁未知。`blocked` 表示至少一个硬门禁明确失败。`unknown` 与 `false` 含义不同，前者表示证据不足，后者表示已经得到否定结论。

## P01 市场环境

P01 给出全市场观察，适合放在每日研究流程的开头。它先用同交易日、有效成交价格的股票形成分母，再计算上涨广度、成交集中度和跌停占比。三项经过同行无关的固定方向变换后形成等权压力分。

宏观部分保留 PMI、PPI、CPI、货币、社融和 GDP 的报告期、公开时间与相邻期变化。月度或季度指标不会被当成每日新信息。停牌、复牌和无成交股票分别计数，未确认完整范围时不会把“没有记录”解释成“没有停牌”。

主要用途：

- 判断当天适合扩张研究范围还是收紧风险门槛。
- 给个股、主题和组合结果补充共同的市场背景。
- 解释成交是否过度集中在少数股票。

主要限制：跌停边界不完整时不发布压力分；宏观相邻期缺失时只给当前观察；P01 不输出指数点位预测或买卖时点。

## P02 主题机会

P02 把行业和题材目录、成员、行情、热度、涨停和资金数据整理成来源可追溯的主题观察。主题名称相同不会自动合并，只有显式实体绑定或有证据的目录别名才能建立关系。

主要加工包括：

- 最新成员数、当前有效成员数和成员代码覆盖率。
- 成员同日价格覆盖、上涨占比和等权收益。
- 主题自身价格变化、上涨／下跌广度和涨停广度。
- 来源内热度排名的倒数、资金方向和每家公司资金量。
- 同日价格与资金的确认状态。

主要用途：发现扩散中的行业或题材，检查上涨是否得到成员广度和资金支持，区分来源内部热度与真实成员表现。

主要限制：成员业务日、有效期或实体关系不完整时，成员贡献保持未知；不同供应商的主题序列不会拼接；排名只说明来源内部关注度。

## P04 基本面档案

P04 按证券、报告期、报表类型和公司类型选择截止时点前可见的财务版本。普通与 VIP 报表只做同口径核对，匹配时不重复计算经济证据，冲突时保留冲突并停止精确评分。

核心指标：

- `cash_margin = 经营现金流 / 营业收入`
- `leverage = 总负债 / 总资产`
- `cash_cover = 货币资金 / 流动负债`
- `balance_error = |资产 - 负债 - 权益| / 资产`
- `Q0 = 100 × [0.40 × P(cash_margin) + 0.35 × P_low(leverage) + 0.25 × P(cash_cover)]`

主要用途：建立公司当前财务质量底稿，为 P03、P13 和 P12 提供父结果。

主要限制：报表类型、公司类型、单位、版本、同行或审计意见不合格时不发布质量分。负权益和亏损会保留为问题研究标记。金融企业不套用非金融企业的三比率模型。

## P06 资本与治理风险

P06 整理未来供给、股权和治理事件。公告、计划、实施和终止阶段分别保存，只有已经确认的批次才能进入累计值。

主要加工包括：

- 未来 30 个自然日的解禁比例。
- 定增计划和已实施定增的稀释比例。
- 可转债全部转股的理论稀释上界。
- 股权质押、股东变化和供给压力指标。
- ST、重点监控、上市状态和重大事件冲突门禁。

主要用途：给所有股票排名提供硬风险门禁，提前看到可能改变流通供给或治理状态的事件。

主要限制：缺少证券关系、事件阶段、币种、单位或期间时不计算稀释；EB 不按 CB 处理；未知风险不能解释成风险为零。

## P07 资金与交易可行性

P07 先核验当天是否停牌、价格是否有效、是否触及涨跌停、是否存在严重异动，再判断资金指标能否进入研究。

主要加工包括：

- 各资金来源的净额分别除以同日合格成交额。
- 可比资金来源的中位数、方向和一致性。
- 资金支持轴与融资、换手、筹码形成的拥挤轴。
- 大宗交易折溢价、陆股通、龙虎榜和席位旁证。

主要用途：判断候选股票有没有实际资金支持，交易条件是否允许执行，以及拥挤度是否已经偏高。

主要限制：少于两个可比资金来源时一致性未知；不同来源金额不会直接相加；匿名席位和局部分钟数据不会外推到全市场结论。

## P03 右侧交易候选

P03先检查回调、低点抬高、整理范围与20日均线转强，再识别放量突破或最近五个观察日内突破后的缩量回踩转强。只有确认价附近、到失效价的风险受控且上方历史阻力空间足够的候选，才能进入评分池。

过去5/20/60日涨幅不参与评分。初始权重为入场风险30%（低为优）、历史阻力空间/风险30%、突破成交额确认20%、同日大单比例10%、财务质量10%。因子与最终名次均在可比同行池内计算，回退层不同的结果不混排。

默认规则要求至少61个唯一日线观察、回调至少5%、整理低点高于此前低点至少0.5%、整理范围不超过12%、现价高于20日均线且均线不下降。突破日成交额至少为此前20日中位数的1.2倍，现价距确认价最多3%、距失效价最多8%，到历史阻力的空间/风险至少2。具体计算、配置与限制见[P03右侧交易候选](P03右侧交易候选.md)。

P04/P06/P07父结果、正PE/PB、同日资金与交易可行性是必要门禁。缺数据、仍在下跌、买入位置过远或门禁失败时，保留原因与结构诊断，分数和名次均为空。

这些阈值是未经回测的初始规则，历史阻力不是预测目标价。P03不自动下单，催化和盈利预期仍需结合P02/P05/P13人工核查。

## P05 预期修正

P05 按报告期、公告时间、事件类型和机构口径整理预告、快报与研报。普通版和 VIP 版一致时只保留一个经济事件，冲突时停止数值比较。

主要加工包括：

- 业绩预告中点和区间宽度。
- 同报告期前后两次预告的中点修正。
- 快报净利润、收入及其审计状态。
- 快报相对预告中点和区间的兑现差。
- 同机构、同期间预测的净利润和 EPS 修正。
- 机构推荐和调研活动的观察覆盖。

主要用途：识别预期上修、下修和兑现偏差，并保留每次公开信息的顺序和机构身份。

主要限制：官方契约缺少 `profit_scope` 时，预告与快报的利润归属不能自动认定一致，兑现差保持未知。不同机构的预测不会平均成统一目标值。

## P08 ETF 暴露

P08 从 ETF 档案出发，连接明确的基准代码、成分权重、申赎篮子、行情、净值、份额和复权信息。基金名称和自由文本基准不会用来猜指数关系。

主要加工包括：

- 基准观察权重、HHI 和篮子与基准的成分重合度。
- 成交额、成交手数、成交额占规模比例和价格边界距离。
- 价格相对净值的溢折价、规模与份额净值恒等式残差。
- 份额变化和按净值估算的申赎变化代理。
- 固定端点复权收益及与基准的口径核对。
- 管理人、分红和做市借券库存旁证。

主要用途：比较 ETF 暴露、集中度、申赎变化和交易可行性；有用户持仓时还能计算组合重合度。

主要限制：基准成分只代表观察到的基准结构，不等于基金实际持仓。缺少 `return_basis` 认证时，基金与基准的跟踪差保持未知。没有用户组合时，ETF 本体结果仍会输出。

## P09 商品传导

P09 按期货品种规格、交割月、报价单位和交易单位组织合约，保留现货、库存、仓单、持仓和企业主营数据的层次。

主要加工包括：

- 远月结算价相对近月结算价的期限结构。
- 结算价相对收盘价、持仓量相对成交量。
- 会员多仓和空仓样本集中度。
- 库存、仓单和到期材料的分层变化。
- 保证金、涨跌幅、最小价位和限仓约束。
- 贵金属现货与期货的显式可比关系。
- 企业主营分部成本率、毛利率和商品暴露证据。

主要用途：观察商品曲线、库存和持仓压力，并把明确的企业商品关系带入后续研究。

主要限制：会员集中度只描述样本，不解释净多空方向；仓库和品级不会随意汇总；没有确认的企业商品关系时不生成受益股票名单。

## P10 跨市场传导

P10 保持市场、币种和会计范围分离，只有单位、币种、业务日和关系都可比时才做跨来源计算。

主要加工包括：

- 外汇中间价和买卖报价差。
- 港股、美股和全球指数的来源内变化。
- HIBOR、LIBOR 和美债名义／实际利率的期限差。
- 港美财务长表的利润率、杠杆和现金流结构。
- 已确认 A/H 配对的提供方溢价核对。

主要用途：观察汇率、海外市场、利率曲线和跨市场公司状态，为主题、商品和组合研究补充外部环境。

主要限制：USD、HKD 和 CNY 不做隐式换汇；公司名称和相同代码不能证明跨市场实体关系；实时港股缺认证行情时间戳时不生成收益率。

## P11 融资尾部风险

P11 将融资余额、转融券、回购利率、银行报价、债券成交、期权和 VIX 分开加工。

主要加工包括：

- 净融资强度、融资余额占两融余额比例和转融券偿还压力。
- 回购利率、SHIBOR 和地方融资指数的期限差。
- 同券同期限银行报价的买卖收益率离散度。
- 债券成交价格极差和最大单笔金额占比。
- 同标的、同到期、同乘数期权组的成交量 PCR 和持仓量 PCR。
- 美国隐含波动变化。

主要用途：观察融资条件是否收紧，区分债券报价与实际成交，并检查期权市场的尾部对冲活动。

主要限制：报价不代表成交；不足两个可比银行样本时不计算离散度；PCR 只描述观察到的期权活动，不给出市场方向预测。

## P12 组合诊断

P12 接受显式持仓 JSON，也可以使用已披露的基金股票持仓。显式持仓优先，权重必须在 0 至 1 之间且总和为 1，同一实体不能重复。

主要产物：

- HHI、最大持仓和前五持仓权重。
- 股票、基金、期货等资产类型暴露。
- 上游产品中同名、同单位比例指标的组合加权值。
- 基金股票部分的已披露市值观察。
- 价格下跌 20% 的明确假设情景。
- 父结果多重集摘要和完整血缘。

主要用途：检查组合集中度、暴露和上游风险信号，定位哪些持仓贡献了主要风险。

主要限制：缺少持仓时输出 `input_required`；基金披露只覆盖已经披露的股票部分；缺少组合资金规模与参与率时不计算清算天数；压力情景是固定假设，不是预测。

## P13 事件论点复核

P13 汇总重大新闻、披露日程、宏观日程、指数公告、名称变更和 P04／P06／P07 的父结果。每个证券的三份上游结果先合成一个 `upstream_bundle`，新闻和其他事件仍逐事件保留。

主要产物：

- 原文片段、事件时间、来源和候选实体。
- `documented_reason`、`temporal_association` 等三值论点。
- 支持证据、反证、硬门禁和人工复核顺序。
- 新闻实体关系和上游产品血缘。

主要用途：检查一条研究论点是否有原文、时间和上游数据支持，形成可复核的事件清单。

主要限制：原因判断必须引用原文；时间相邻只表示已经核对同窗观察，不构成因果关系；无证券代码或实体歧义的文本等待人工确认；历史不足时不计算事件 CAR。

## 怎么运行

先生成与参考库、截止时点和容量边界绑定的配置，再运行和校验产品库。

```bash
REFERENCE=/path/to/reference.duckdb
PRODUCT_OUTPUT=/path/to/products.duckdb
PRODUCT_CONFIG=/path/to/products-config.json
PRODUCT_AUDIT=/path/to/products-config.audit.json
ANALYSIS_AS_OF=2026-10-04T12:00:00Z

uv run tushare-hub research-all build-config \
  --reference "$REFERENCE" \
  --output "$PRODUCT_CONFIG" \
  --audit "$PRODUCT_AUDIT" \
  --as-of "$ANALYSIS_AS_OF"

uv run tushare-hub research-all run \
  --reference "$REFERENCE" \
  --output "$PRODUCT_OUTPUT" \
  --config "$PRODUCT_CONFIG" \
  --as-of "$ANALYSIS_AS_OF"

uv run tushare-hub research-all validate \
  --reference "$REFERENCE" \
  --output "$PRODUCT_OUTPUT"
```

默认运行十三个产品。只运行某个产品时重复使用 `--product`：

```bash
uv run tushare-hub research-all run \
  --reference "$REFERENCE" \
  --output "$PRODUCT_OUTPUT" \
  --config "$PRODUCT_CONFIG" \
  --as-of "$ANALYSIS_AS_OF" \
  --product P05

uv run tushare-hub research-all run \
  --reference "$REFERENCE" \
  --output "$PRODUCT_OUTPUT" \
  --config "$PRODUCT_CONFIG" \
  --as-of "$ANALYSIS_AS_OF" \
  --product P03
```

依赖会自动展开。P03与P13会带上P04／P06／P07；P12会带上十三个默认产品。

`run` 返回 0 表示完整结果，返回 2 表示结果已经发布但仍有明确数据缺口，返回 1 表示执行失败。退出码 2 的产品库仍应继续执行 `validate`。

## 怎么读取

按产品读取当前批次结果：

```bash
uv run tushare-hub research-all results \
  --output "$PRODUCT_OUTPUT" \
  --product P03 \
  --limit 20
```

查看逐接口消费审计：

```bash
uv run tushare-hub research-all audit --output "$PRODUCT_OUTPUT"
```

`results` 输出 JSONL，单次最多 512 条。建议按下面的顺序解释一条结果：

- 先核对 `product_id`、`entity_id` 和 `analysis_as_of`。
- 再看 `state`、`decision_allowed` 和硬门禁。
- 有分数时同时读取 `rank`、`peer_count`、`feature_profile` 和贡献项。
- 分数为空时读取 `gate_codes` 和未知指标的 `reason_codes`。
- 需要复核时沿 `evidence_refs` 回到参考库，沿 `parent_result_ids` 查上游产品。

## 怎么组合使用

每日研究先用P01了解市场环境，再用P02发现主题扩散，用统一P03筛选已经转强且入场位置受控的公司。随后读取P04财务底稿、P05预期修正和P13事件证据，人工核对交易逻辑。P03没有分数时先看失败原因，不能用历史涨幅代替结构确认。

ETF 研究以 P08 为主，P01 提供市场背景，P10 和 P11 提供利率、汇率和融资环境。P08 的基准结构不能替代基金实际持仓。

组合复核以 P12 为入口，沿父结果查看每个持仓的 P04、P06、P07、主题、商品和跨市场证据。上游指标缺失时，组合层不会填零。

## 当前正式数据能做到什么

原十三产品正式批次包含 176,095 条结果，独立 `validate` 返回 `valid=true`。206 个接口都达到 registered、assigned、executed、readable 和 configured，其中 91 个接口产生了通过门禁的业务观测，201 个接口仍有至少一项未解决原因。

此前三榜批次的35,466条结果属于旧模型历史验收，其中三榜各5,911条且无有效名次。它不能证明统一P03已经生成真实市场排名。新模型须用完整、已认证的行情窗口和父产品重新生成独立批次。

这说明产品的采集、加工、降级、存储、查询和重算链路已经可用。统一P03是否可排名取决于每个候选的窗口、结构、单位、财务和交易门禁。现有旧批次不会原地改分。

## 使用边界

- 产品只读取 `accepted` 数据，隔离记录不会进入指标。
- 公告时间、有效时间、观察时间和报告期分别处理。
- 相同代码、相同名称或相邻时间不能自动证明实体关系和因果关系。
- 普通接口与 VIP 接口一致时只算一份经济证据，冲突时保留冲突。
- `historical_pit_certified` 和 `historical_tradable` 当前均为 `false`。
- 产品不读取券商账户，不自动下单，不输出收益承诺。
- 分数只在同一产品、同一口径和同一同行池内解释。
- `valid=true` 证明存储和重算一致，不证明数据齐备或策略有效。
