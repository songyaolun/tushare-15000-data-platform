# 本地数据参考

本地参考把接口数据整理成可复用的数据集，后续研究、报表和决策产品都可以直接读取。它不依赖既有十类产品，也不要求先设计前端。每个已登记接口都有采集状态；有权限且请求成功的数据经过标准化和逐行验收后，分别发布到合格区或隔离区。

共享产品能力由独立的[产品加工基础层](产品加工基础层.md)承接。它只读此参考库，按 206 接口矩阵核对契约并写入独立 `products.duckdb`。`accepted` 行还需通过实体、时间和单位门禁才可用于特征；P01—P13 业务引擎尚未实现。

## 正式采集

先按[真实接口接入](真实接口接入.md)同步目录，再执行：

```bash
uv run tushare-hub --db /path/to/hub.duckdb reference build \
  --live \
  --credential-file /path/to/existing.env \
  --output /path/to/local-reference \
  --parameters /path/to/collection-parameters.json
```

凭据文件只读取 `TUSHARE_TOKEN`，不会复制到数据目录。线上访问使用 HTTPS；测试使用合成响应，无需真实账户。真实原始数据、数据库和运行报告应存放在仓库外。

参数文件按接口列出完整业务范围。例如：

```json
{
  "daily": {"trade_date": "20260930"},
  "balancesheet_vip": {"period": "20260630"},
  "cn_cpi": {"start_m": "202509", "end_m": "202608"},
  "stock_basic": {"list_status": "L"}
}
```

接口参数也可以是对象列表，例如 `"etf_sh_cons": [{"ts_code": "510300.SH", "trade_date": "20260930"}, {"ts_code": "510050.SH", "trade_date": "20260930"}]`。每个对象是一个独立分区，清单记录各分区的结果；一个分区失败不阻止其他分区。需要突破全市场分页上限时，应按已知证券范围拆分。

参数完整替换该接口的默认参数。未列出的接口沿用已有政策范围，其中可能是单只证券、单份报告或历史日期。运行前应明确这些范围；成功取完一个请求，并不意味着已经取完全部历史或全市场。`manifest.json` 保存实际参数及每页证据，消费数据时应先查看它。

`--apis daily,adj_factor` 可选择接口；`--refresh` 强制重新请求。默认仅复用已取完声明范围、账户、来源、参数和规则版本一致且文件校验通过的正式产物，能力探测的样本不用于替代正式采集。每个接口完成后写入清单，中断后可以重新运行。

采集显式请求官方输出字段。提供方返回 `has_more=true` 时继续分页，返回 `false` 时记录本次响应范围结束。未提供分页状态时，只有契约支持的短页或已完成的组合查询能作为结束依据。重复页、无进展、页数上限和中途请求失败都保留不完整状态。

## 文件和查询入口

| 路径 | 用途 |
| --- | --- |
| `inventory.csv` | 可用表格工具打开的全接口清单、行数、范围和字典路径 |
| `catalog.json` | 全目录状态、实际请求范围、行数及产物路径 |
| `reference.duckdb` | 独立本地数据库，可直接用 SQL 查询 |
| `quality-audit.json` | 跨接口核对结果和未检查范围 |
| `datasets/<api>/manifest.json` | 单接口采集、质量及文件校验证据 |
| `datasets/<api>/source_dictionary.json` | 无数据时也可查看的来源字段说明 |
| `datasets/<api>/runs/<run>/dictionary.json` | 本次规范化规则、主键、单位及实际输出列类型 |
| `datasets/<api>/runs/<run>/accepted.parquet` | 通过逐行规则的数据 |
| `datasets/<api>/runs/<run>/quarantine.parquet` | 隔离记录、问题码及原始字段 |
| `raw/<api>/...` | 标准化之前保存的原始响应 |

每个非空数据区同时提供 JSONL 和 Parquet。空数据区保留空 JSONL 和行数信息，不创建 Parquet 或 SQL 数据表。路径和校验和以清单为准，应用不要自行猜测最新运行目录。

```python
from pathlib import Path
import duckdb

reference_root = Path('/path/to/local-reference')
with duckdb.connect(str(reference_root / 'reference.duckdb'), read_only=True) as connection:
    print(connection.execute(
        'SELECT api_name, status FROM catalog ORDER BY api_name'
    ).fetchall())
    print(connection.execute('''
        SELECT ts_code, trade_date, close, observed_at
        FROM accepted.daily
        ORDER BY ts_code
        LIMIT 20
    ''').fetchall())
```

`accepted.<api>` 和 `quarantine.<api>` 分开保存。`catalog.manifest` 是完整 JSON 清单，可以检索参数、质量结果和页证据。读取 Parquet 时同样应带上对应清单，尤其不要忽略 `partial` 状态。

## 标准化保留哪些信息

日期转换为日期类型，明确声明的分钟时间按来源时区转换为 UTC。月份、季度、报告期、公告日和观察时间保留各自含义。披露修正日期列表保存为日期数组，交易时段和年结月日等文本不会强行转换成完整日期。

数值按官方类型解析，单位按已登记政策转换。`source_fields` 保留源字段和值，`source_units` 和 `standard_units` 分别说明转换前后的单位。空值保持为空，不能解析的值进入隔离区。

`business_group_key` 表示稳定的业务事件组，`business_variant_key` 区分同组内没有官方编号的版本、批次或匿名席位，`source_record_id` 由接口、观察时间、请求身份、响应摘要和页内位置组成。`business_dimensions` 和 `business_variant_dimensions` 保存用于构造两层身份的字段。同内容记录合并并保留全部 `source_occurrences`；不同来源变体分别保存，不用金额覆盖另一条记录。财务报表的 `update_flag` 属于官方版本维度，两种版本都保留。

每条合格记录带有质量层级。`verified` 可作为产品默认输入；`usable_with_annotation` 可用，但产品必须读取对应的无成交、空值或身份说明。零成交且开高低为0时，标准开高低转为空值，原始0仍在 `source_fields`；非零收盘标记为提供方参考收盘，所有价格为0时标记为没有价格观测。有成交量但价格缺失或矛盾的记录继续进入隔离区。

`observed_at` 是这次采集批次的观察时间，不会用报告期倒填。当前参考不认证历史回测资格，`historical_pit_certified` 始终为 `false`。需要历史回测的产品应另行验证公告时间、修订版本和当时可见性。

## 怎样理解验收状态

| 状态 | 含义 |
| --- | --- |
| `accepted` | 有数据、逐行验收通过，且有本次声明请求范围的结束证据 |
| `partial` | 存在可用行，但含带注释记录、隔离行或采集范围缺口 |
| `quarantined` | 已取回记录，但没有记录通过当前逐行规则 |
| `empty` | 请求未取得业务记录；不能由此推断接口无权限或全市场无数据 |
| `unauthorized` | 本次请求被提供方按权限拒绝 |
| `transient_failure` | 网络或服务限频等临时问题 |
| `contract_failure` | 参数或响应契约不满足，需核查实际原因 |
| `processing_failed` / `rebuild_failed` | 本地处理或离线校验失败 |
| `excluded` | 私有组合查询、写操作或非 API 交付项；保留目录说明 |

逐行验收检查字段类型、业务键、重复冲突、价格关系、量额非负及复权因子。业务字段的可空性以明确规则为准，官方列出一个输出字段不等于它永不为空。零成交记录中的异常价格不会被自动改成正确价格。

`quality-audit.json` 另行核对 A 股日行情能否对应每日指标、复权因子、证券名录和所属交易所的交易日历。缺表、缺列返回 `not_checked`，缺对应记录返回 `failed`。另按证券名录中的上市、退市日期核对已采交易日应有证券，并列出停牌可解释和无法解释的缺项。该检查依赖观察到的名录和停复牌记录；整日缺采、历史证券范围及其他市场的跨表验收仍需单独完成。`accepted` 不能替代这些检查。

Tushare 的 `trade_cal` 官方参数没有列出北交所。本地数据库因此同时保留原始日历缺口和 `derived.cn_equity_trade_calendar` 产品日历。北交所日期有实际行情时使用 `observed_bse_market_activity`，没有行情样本但上深开闭市一致时使用 `aligned_sse_szse_calendar`，上深不一致时保持 `unresolved`，不猜测开闭市状态。

小时限频接口在清单的 `collection_policy` 中记录限速、分区策略和临时失败后的 `retry_eligible_at`。`hk_daily` 按交易日整批取市场，`stk_mins` 按证券和交易日排队；系统不会在同一限频窗口立即重放请求。

## 规则修订后离线重建

```bash
uv run tushare-hub reference rebuild --output /path/to/local-reference
```

可加 `--apis daily,adj_factor` 只重建指定接口；其他接口在文件校验通过后保留原产物。

重建先核对原始文件校验和、接口身份及响应摘要，再使用当前规则生成新的标准数据、隔离记录和数据库。它不读取凭据、不请求网络，也不改变原始观察时间。发现原始文件损坏时停止发布该接口的旧产物，其余接口继续处理。

后续产品应从业务问题确定历史长度、市场范围和质量要求，再按参考目录补齐所需数据。这样可以复用已经采集的数据，也能明确看到哪些问题仍缺历史或缺接口权限。
