# 接口目录与权益维护

这份目录从 Tushare 公开文档发现接口，不使用账户 Token，也不调用数据接口。快照记录的是抓取时可达的文档集合，不能证明已经发现官方全部接口，更不能证明某个账户已经开通全部权限。

## 快照与来源

`fixtures/catalog/official` 保存官方目录、权益总表及详细文档。抓取清单 `index.json` 逐页记录来源 URL、成功或失败状态、错误类型及文件摘要。快照只留下导航和文档正文；登录界面、脚本和凭据示例实参已经移除或脱敏。摘要对应净化后的本地文件，清单以 `sanitized_documentation` 标明这一点。

`schema-summary.json` 从详细页保留输入参数和输出字段说明，便于复核字段含义和单位。`summary.json` 记录接口数量、生命周期分布及未解决项目。`markdown/每日筹码及胜率.md` 是官方正文的 Markdown 节选，用于重放相同的权益规则。

两个入口分别是[官方数据目录](https://tushare.pro/document/2)和[积分与频次权限对应表](https://tushare.pro/document/1?doc_id=290)。在线发现只允许 HTTPS 的 `tushare.pro/document/1`、`tushare.pro/document/2`，拒绝外域及重定向；最多并发四个公开文档请求。详细页中出现的新文档链接也会继续遍历。

## 目录同步与复核

`fetch_documentation(destination)` 是显式联网操作，返回成功保存的 HTML 路径及抓取清单路径。`sync_catalog(paths, verified_at, policies)` 只读本地 HTML、Markdown 和抓取清单，不发网络请求。直接向它传目录即可重放整个快照。`load_policies()` 读取包内政策，未知接口不会获得兜底政策。

接口名以正文声明为主，同时保留同页明确公布的 VIP 及扩展接口。导航标题不会直接充当 API 名。导航已经列出、但缺少可解析详情的入口仍会生成 `unresolved_doc_*` 记录。抓取失败会进入目录证据，已有旧文件不能覆盖本轮失败事实。

每条权益证据保留来源及原句。积分门槛、每次行数、每分钟频次分别提取；价格、每日总次数和账户等级不会混作接口限制。冲突保留双方证据并设置 `needs_review`，独立权限保留分类标签。文档待复核不阻止只读探测；真实采集依据同账户、同政策的成功请求证据放行，继续检查数据契约。离线 fixture 仍使用严格的文档检查，不能借离线成功声称账户有权限。

`updated_at` 保存文档中明确的数据更新说明，例如“交易日每天 15 点～16 点之间入库”。它不是抓取时间或网页修改日期；没有明确说明时保持空值，并记录 `missing_fields`。`last_verified` 单独记录本次核验时间。

## 采集政策按数据粒度配置

`src/tushare_entitlement_hub/data/policies.json` 是显式政策清单。每个接口独立保存主键、分片字段、必需字段、原始单位、回看窗口和目标消费者，不能通过增加一个通用默认政策消除新接口债务。

| 数据类别 | 代表接口 | 主键或分片重点 | 目标消费 |
| --- | --- | --- | --- |
| 基础与日历 | `stock_basic`、`trade_cal`、`stock_company` | 股票代码快照；交易所与日历日 | 个股档案、事件日历 |
| 股票行情 | `daily`、`weekly`、`monthly`、`daily_basic`、`adj_factor` | 股票代码与交易日；量价字段与复权因子分开保存 | 市场总览、个股档案 |
| 财务与 VIP | `income`、`balancesheet`、`cashflow`、`fina_indicator` 及 VIP | 证券、报告期、公告时间；财务三表还区分报表类型 | 个股档案 |
| 公司行动与股东 | `dividend`、`repurchase`、`share_float`、`top10_holders` | 公告、生效日期和股东身份分别参与事件粒度 | 事件风险、股东分析 |
| 资金与两融 | `moneyflow`、THS/DC 资金接口、`margin`、`margin_detail` | 证券或市场与交易日；不同来源单位独立保留 | 资金行为、行业轮动 |
| 龙虎榜与题材 | `top_list`、`top_inst`、THS/DC/TDX 板块 | 龙虎榜原因及营业部；板块成员有效日期 | 市场情绪、题材轮动 |
| 指数与申万 | `index_weight`、`index_member_all`、`sw_daily` | 指数、成分、日期；行业成员记录进入时间 | 市场总览、行业轮动 |
| 基金与 ETF | `fund_nav`、`fund_portfolio`、`etf_share_size`、PCF 接口 | 基金净值日与公告日；持仓标的；篮子成分 | ETF 与基金中心 |
| 期货与期权 | `fut_daily`、`fut_holding`、`fut_wsr`、`opt_daily` | 合约、交易日、会员或仓库等业务维度 | 衍生品与固收 |
| 可转债与债券 | `cb_daily`、`cb_call`、`cb_rating`、`repo_daily` | 债券、日期、赎回或评级事件类型 | 衍生品、事件风险 |
| 外汇与宏观 | `fx_daily`、Shibor、GDP、CPI、PMI | 币种和日期；月度与季度保持原期间粒度 | 宏观环境 |
| 特色研究 | `cyq_perf`、`cyq_chips`、`stk_factor_pro`、`hm_detail`、`stk_surv`、`report_rc` | 筹码价格档、游资身份、调研事件、预测机构和预测期 | 个股研究、市场情绪 |

分片不能改变接口参数语义。财务 VIP 按 `period` 请求；月度宏观使用 `m/start_m/end_m`，GDP 使用 `q/start_q/end_q`，期货周报使用 `week/start_week/end_week`。这些接口不能统一发送 `start_date/end_date`。

`minimal_params` 专供探活，证券和日期均为确定的窄范围示例。例如 `daily` 使用一只股票和一个交易日，VIP 使用一只股票和一个报告期。它们不是全市场采集的默认范围。生成采集任务时须清理探活证券和日期，再合并用户明确的范围及分片参数；交易所、频率和接口要求的类型仍须有效。文档没有过滤参数的静态表只能请求一次完整快照。历史示例可能得到空数据，不能用空结果证明已经获得真实数据覆盖。

单次行上限缺失时，政策中的 `page_size=1000` 仅是本地保守值。目录仍保留上限未知及复核标记，不把 1000 写成官方配额。分页支持也只依据明确的参数契约，不能把“可以循环提取”自动解释成支持 `offset`。

## 时点与单位

公告时间、报告期、生效日期与观察时间分别保存。财务数据优先使用实际公告时间，并同时受本地 `observed_at` 约束。宏观历史值通常缺少版本发布时间，只能作为观察后的快照使用；不能把季度末或月份末当作市场已经知道该值的时点。

THS、DC、TDX 等来源的成交额、资金流和流通股本可能使用不同单位。政策只记录文档明确的单位；未知字段保留原值并禁止跨源换算。期货的合约乘数、交易单位来自合约元数据，不给所有品种套用股票的“手”或“股”。

事件接口缺少稳定事件 ID 时，政策采用文档可提供的业务复合主键。例如大宗交易包含交易双方、价格及数量。来源若真的返回内容完全相同的多笔事件，仅凭这些字段仍无法区别，原始响应必须保留，后续要补充来源事件标识后才能宣称完成去重治理。

## 独立权限与例外入口

历史和实时分钟、实时日线、公告新闻、ETF 实时参考、港美股、盘前股本、集合竞价、互动问答、政策库、券商研报和央行报告保留官方权益分类，但统一参加公共只读实测。量化因子库、债券接口和指数公告同样以当前账户的真实响应判断能否接入，不再按数据类别隔离。

官方权益总表与港美股部分详情存在积分描述冲突，双方证据都保留。实测成功可以放行当前账户采集，但不会改写官方授权规则或推断其他账户也有权限。

`pro_bar` 是 SDK 组合方法，现通过本地适配器组合底层 HTTPS 接口，已有独立输出政策。支持范围及复权约定见[真实接口接入](真实接口接入.md)。用户组合的 `p_save`、`p_delete` 会修改账户，不作为探测请求；`p_get`、`p_list` 可通过显式选择执行私有只读探测。

官方[期货 Tick 文档](https://tushare.pro/document/2?doc_id=314)明确写明不提供 API，仅通过 CSV 网盘交付。目录保留这一入口及 `non_api_delivery` 证据，不编造 `ft_tick` 接口，也不把它算入已发现 API 数。

## 当前快照仍有明确债务

基线保存 284 份公开文档，发现 250 个 API 或 SDK 方法，并单列 1 个非 API 的 Tick 交付入口。250 条政策已登记，包含 `pro_bar` 的组合输出契约。基线文档统计有 62 条需要复核、53 个 API 的单次上限未知，251 条登记中有 204 条未取得明确的数据更新说明。文档缺项继续保留，账户实测结果单独记录；这些数量不代表已采集或已消费。

| 接口 | 状态 | 依据 |
| --- | --- | --- |
| `pro_bar` | 研究，权限依底层资产 | 本地适配器组合底层 HTTPS 请求，已实测股票日线样本 |
| `p_save` | 范围阻断，权限未知 | 创建或修改用户自选组合，属于账户写操作 |
| `p_delete` | 范围阻断，权限未知 | 删除用户自选组合，属于账户写操作 |
| `p_get` | 私有只读，须显式选择 | 查询用户组合成分，不参加默认公共扫描 |
| `p_list` | 私有只读，须显式选择 | 查询用户私有组合，不参加默认公共扫描 |
| `fut_weekly_monthly` | 研究，权限未知 | 详情给出每次 6000 行，没有明确积分门槛 |
| `hsgt_top10` | 研究，权限未知 | 详情未披露权限要求与单次上限 |
| `namechange` | 研究，权限未知 | 详情未披露权限要求与单次上限 |

目录中的范围标记不是账户实测失败。`fut_weekly_monthly`、`hsgt_top10`、`namechange` 已经返回真实非空样本，文档权限未知不再阻止其接入。`broker_recommend` 的“积分达到 6000 即可调用”已解析，不列入权限未知。完整实测状态以本地扫描报告为准。

## 后续维护要求

更新时先保存新快照和抓取清单，再离线比较新增、消失和字段变化。新增接口必须增加具体政策及真实消费者，未知接口保持 `unclassified`，质量门禁应失败。删除或失效的文档不能静默删除已有目录记录。

把一条接口计为覆盖，还需要探活、原始落盘、质量检查和实际消费证据。目录登记、政策填写和离线样例通过分别反映不同进度，均不能单独代表真实账户数据已经接入。
