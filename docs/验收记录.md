## 虚拟内存限制修复复验

移除了验收脚本中的 `ulimit -v` 及 4 GiB 虚拟地址空间预算。该限制会把分配器预留地址空间误当作实际内存占用，导致冷启动环境中的分配失败。各验收阶段仍按顺序执行，依赖安装、Ruff 与数值库保持单任务或单线程，DuckDB 保留自身内存限制。

使用已安装的 CPython 3.11.9 基础解释器创建此前不存在的 uv 虚拟环境，未复用仓库 `.venv`，也未在验证外层添加虚拟内存限制。完整 `uv run --no-project bash scripts/ci.sh` 返回成功：Ruff、13 个模块的严格 mypy、333 项测试和 100.00% 行覆盖率均通过。另以新缓存目录执行 `mypy --no-incremental`，13 个模块全部通过，未出现内存分配失败。离线产品为 20 个文件，Parquet 可读并包含 11 行、11 个接口。

该轮 CI 使用预装固定 uv 0.12.21 的 Python 3.11 镜像；命令中没有直接调用 Python、python3 或 pip。运行环境、缓存与日志均在 `/tmp`，未纳入提交。源码与测试用例未改动。
