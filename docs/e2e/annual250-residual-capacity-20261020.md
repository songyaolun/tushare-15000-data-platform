# 剩余超限与分钟覆盖诊断

适用revision为`ed521e32cde09cedff2030cca946113b76c03704`，无依赖仓变化。使用已冻结的
1%与0.5%八账户及只读行情缓存，Python3.11通过`uv run --frozen`执行并清除PYTHONPATH。
本轮不训练、不重放交易、不下载新数据，无凭据依赖。诊断不改变原CSV和模型。

## 离线诊断

1. 冻结八账户88份输出、既有诊断、分钟清单及脚本哈希。沿用已揭示结果的诊断，不冒称盲测。
2. 对全部70105笔成交聚合同证券日金额，以执行日成交额为事后分母。定位全部超1%记录，
   逐笔列出历史20日中位数、昨日金额、历史限额、当日金额、买卖方向、退出原因、成交和请求股数。
   验证参与率分解为历史限额系数、历史基数／当日金额和限额使用率三项乘积，不用当日量改预算。
3. 按年度、买卖、退出原因和证券汇总；保留所有证券及两范围双成本。独立SQL重算计数和金额，
   不因个别证券异常删除样本。核对各账户全部日级资金缺口，明确同开盘时间顺序尚未证明。
4. 在现有Tushare缓存范围清点分钟正式分区、原始探测样本及清单，分别报告请求失败、成功样本、
   可解析记录、证券日、起止时点和与实际成交证券日的交集。重复文件不重复算覆盖，样本不外推。
   来源时区、单位或时间语义不明时标为未认证；没有分钟成交或回报时间不能宣称资金顺序验证通过。
5. 结束时核对冻结文件未变，保存全量明细、独立校验、数据覆盖清单与报告。未知项和失败原样保留。

通过标准是全部成交分母及聚合恒等式通过、分钟证据边界可复核，并据此选择下一项可执行研究。
本轮不以诊断通过声称主账户日历CAGR超过250%或执行容量认证。

本次无生产代码、Schema、前端或跨端行为修改，桌面及390x844浏览器验收not applicable。
跨端数据一致性以冻结文件哈希为准，不宣称Mac实测。真实数据链路本轮不执行；下载、
合并、部署、飞书、交易和注册调度不在本阶段授权内。证据产物存放私有缓存，仓库只提交报告与计划。
