# 年化250%研究：因果流动性约束验收

本阶段先量化受约束后的收益损失，不把新增约束或单轮完成当作250%目标达成。
适用 revision：从 `c37f49474b2c6f10d57dfb24f9313996c465fd1e` 起的本分支流动性
提交，精确执行SHA写入实验清单；不更新跨仓依赖。复用已冻结47列评分和原始面板，
以独立Python 3.11环境运行 `uv run --frozen`，不加载凭据、不读取个人账户。

## 先冻结的协议

- 每证券每日买卖合计名义金额，上限为过去20个交易日成交额中位数与前一日
  成交额较小值的1%。成交额保留千元口径，计算上限时只乘1000一次。
- 窗口只包含执行日前的完整交易日。窗口不足、非有限或负金额时上限为零。
  已知零成交保留，不当作缺失剔除；前一日为零时当日停单。当天完整成交量和
  成交额只作事后诊断，不用于开盘订单大小，也不据此有利取消订单。
- 买入仍满足整手、现金、费用、单股5%、行业40%和原候选限制，因流动性缩量
  后不自动补单。未卖完的仓位保留原退出原因，随后合格开盘继续尝试；部分卖出
  按整手向下取整，剩余尾数在全部能成交时一起卖出，科创板部分卖出按1股步长。
- 每次部分卖出按成交股数占当前股数的比例分摊成本与已确认分红，残余成本、
  股数及分红留在同一批次。停牌、跌停、T+1和送股锁定继续阻止卖出。
- 部分卖出只释放实际现金。配对换仓及预备名额须等对应旧仓全部退出才释放，
  不能因第一次部分卖出就把剩余旧仓当作已清空。
- 四账户口径不变：100万原范围主目标、12万主板对照，各含正常/双成本。
  baseline47与holding15均重跑，共八个受约束账户，旧产物保持冻结。

真实案例：2026-08-19的603808.SH，过去窗口始于2026-07-22，前一日成交额
23035.981千元，20日中位数33377.0875千元。本协议限额230359.81元；旧holding15
主账户该笔为4979020.266元。约束计算不读取当日18102.951千元的最终成交额。

## 离线必跑与通过标准

规则测试覆盖参数边界、历史窗口、缺失/零值、改动当天及未来量不影响上限、主板
整手/尾数与科创步长。执行测试覆盖部分卖出多日排队、停牌/跌停延迟、成本与分红
分摊、资金不能提前使用、T+1、配对换仓仅在完全退出后释放。关闭新规则时默认
账户旧字段须精确一致，新增模块目标覆盖率100%。

真实缓存八账户必须通过独立CSV核算：部分成交次数与完全退出批次数分开报告；
逐笔费用、股数、成本、分红、现金、日净值及250日CAGR/年度收益一致。独立重新
计算每笔执行日之前的上限，并检查同证券当日买卖合计不超过上限。全部容量与价格
异常保留，不能删分母。明确报告相对旧基准的收益变化、回撤、敞口、费用及退出延迟。

源数据检查复用只读DuckDB daily/stk_limit与规范分红原文，实际执行日amount只用于
事后参与率。没有开盘分钟数据仍不能声称分钟容量认证。真实新数据采集为可选路径，
本阶段不执行。缺失来源、账本错误或使用未来量时失败关闭，不选报收益。

桌面/390x844手机浏览器和跨端UI一致性：not applicable，本阶段无前端变更。
外部副作用：不发飞书、不部署、不合并、不交易、不注册调度；后继真实写操作仍需
显式授权。证据保存到私有annual250实验缓存，报告、E2E、代码和测试随阶段提交。
