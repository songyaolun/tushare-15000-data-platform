## 经实测修正训练并发

用户要求使用多核并指定每组 16 线程。原本轮 runner 显式设置 OpenMP、OpenBLAS、
MKL 均为 1；这不是算法要求。机器有 64 核 affinity，各级 cgroup CPU quota 均无限制。
旧等权 51200 轮的 5318 秒计时实际使用 OpenMP 4 线程，不能当成本轮单线程的预计耗时。

先以 half252 的同一批 490655×47 训练输入、全部 520690 候选、相同标签与权重，
固定 32 轮，在 1／2／4／8／16 线程下各做三次诊断；再以固定 256 轮对 1／8／16
线程各做三次复核。只改变诊断轮数与 OpenMP 线程数，BLAS、MKL 始终为 1，不回放
诊断模型、不参与收益选型。所有档位的同轮数模型 SHA 与全部候选预测逐字节一致。

256 轮拟合中位时间分别为 31.629／6.550／4.448 秒，原生预测为
10.203／2.029／1.384 秒；可移植推理单次为 17.435／16.879／17.561 秒，后者没有
明显加速。短程结果不能证明 51200 轮跨线程始终逐字节相同，也不能把拟合加速倍数
当成整条链路的加速倍数。

据此采用三个模型并行、每模型 `OMP_NUM_THREADS=16`，BLAS 与 MKL 保持 1；
48 是线程上限合计，不代表独占 48 个物理核。原后处理先停止，再停止原 runner 与
其三组子进程；原日志、协议和未完成模型目录保留在私有中断证据中。新 runner 启动
前须确认旧生产者与消费者都已退出，没有成功完成标记，且没有重复账户审计。

原预登记与原 spec 不覆盖；并发修订另存新执行 revision、原协议 SHA、诊断证据 SHA
及三个新 spec SHA。新训练仍是原 51200 轮、47 列、31 叶深 5、相同随机种子和权重。
每个完整新模型继续要求原生与可移植推理逐条一致，其后仍按本计划完成全部 32 账户。
本次仅改变私有执行并发与文档，业务源码未变化，复用已通过的权重单测；文档执行
`git diff --check` 与提交钩子，不重复已通过的等权账户和测试文件。
