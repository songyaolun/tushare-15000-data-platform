# P02 主题机会使用说明

P02 用来回答三个问题：哪些主题正在扩散，资金和注意力是否跟上，涨停事件有没有持续性。它输出本地数据表，不负责自动交易，也不把评分解释成上涨概率。

## 正式主榜采用完整的同花顺口径

正式主榜使用 `ths_index` 和 `ths_member` 定义同花顺主题。东财、通达信和开盘啦保留独立分榜，不把不同来源的同名主题直接揉成一个主题。

跨来源共识要求名称规范化后完全相同，并且成员 Jaccard 重合度至少为 30%。名称模糊相近、只有成员相似或只有名称相同都不会合并。

## 七项指标怎么计算

综合分使用以下固定权重：

| 指标 | 权重 | 计算口径 |
|---|---:|---|
| 成员上涨广度 | 20% | 有行情成员中，上涨股票所占比例 |
| 成员等权收益 | 20% | 有行情成员的简单平均收益，不按市值加权 |
| 资金强度 | 20% | `moneyflow_cnt_ths.net_amount / company_num` |
| 热度强度 | 15% | 主题成员在完整同花顺热榜中的倒数排名之和，再除以有效成员数 |
| 涨停广度 | 10% | 收盘价达到 `stk_limit.up_limit` 的成员占有效成员比例 |
| 连板强度 | 10% | 首板为 0，二板开始计分，五板封顶，再除以有效成员数 |
| 涨停原因一致性 | 5% | 至少两只有明确原因的涨停成员中，出现最多的原因标签占比 |

每项原始指标先在同一交易日、同一来源的候选主题中计算平均秩分位，再按权重加总：

```text
原始综合分 = 100 × (
  20% × 上涨广度分位
+ 20% × 等权收益分位
+ 20% × 资金强度分位
+ 15% × 热度强度分位
+ 10% × 涨停广度分位
+ 10% × 连板强度分位
+  5% × 原因一致性分位
)
```

五至十九个有效成员的主题会向 50 分收缩：

```text
最终分 = 50 +（原始综合分 - 50）× min(1，有效成员数 / 20)
```

五个成员只保留 25% 的偏离，十个成员保留 50%，二十个及以上不收缩。

## 正式主榜的发布条件

全局数据先通过这些检查：

- `trade_cal`、`daily`、`stk_limit`、`ths_hot`、`moneyflow_cnt_ths` 和 `kpl_list` 最近 20 个交易日都有完整范围证书。
- `stock_basic`、`ths_index` 和全部 1,666 个 `ths_member` 分区已经认证。
- 目标交易日在所有日频必需接口的证书中。
- 业务键唯一、单位认证通过，没有未处理的失败分区。

每个主题还要通过这些检查：

- 至少 5 个成员有目标日合法行情。
- 行情覆盖率至少 90%。
- 涨跌停边界覆盖率至少 90%。
- 资金强度已知。
- 七项指标都能计算。

任何一项未知都不会补成 0，也不会把缺失指标的权重分给其他指标。

完整热榜已经认证时，未上榜成员的热度贡献为 0。热榜采集不完整时，P02 全局状态为 `incomplete`，不发布综合主榜。

## 输出表的用途

`p02.main_ranking` 是正式综合主榜。它包含七项原始指标、来源内分位、原始分、样本收缩系数、最终分、排名、成员数和覆盖率。

`p02.price_diffusion` 是价格扩散榜。它只要求至少五个有效成员和 90% 行情覆盖，使用上涨广度分位与等权收益分位各 50%。资金、热度或事件范围暂未就绪时，这张表仍可用于观察，但不能冒充正式综合榜。

`p02.event_evidence` 保存每个主题的涨停成员、板数和标准化原因标签。开盘啦涨停原因属于供应商事件解释，不当作上市公司公告事实。

`p02.source_ranking` 保存同花顺、东财、通达信和开盘啦各自的价格扩散分榜。各来源使用自己的成员范围，分数只在来源内部比较。

`p02.cross_source_consensus` 保存通过严格名称和成员重合规则的共同走强主题，包含来源数、各来源主题代码、成员 Jaccard 重合度和平均扩散分。

`p02.evidence_link` 只保存主题代码到来源记录 ID 的关系。原始来源字段仍在统一参考库中，不复制到产品库。

`release` 表保存本次运行的目标日、参考库指纹、readiness、缺口、权重和 release ID。

## 生成本地结果

先把静态目录、20 日输入和完整主题成员组合成统一参考库：

```bash
uv run tushare-hub reference compose \
  --source /path/to/static-reference \
  --source /path/to/p02-inputs \
  --source /path/to/ths-theme-members \
  --output /path/to/p02-unified-reference
```

再构建 P02：

```bash
uv run tushare-hub research-all p02-build \
  --reference /path/to/p02-unified-reference/reference.duckdb \
  --output /path/to/p02-products \
  --trade-date 2026-10-14
```

状态为 `ready` 时退出码为 0。范围尚未齐全时仍会写出价格扩散榜和诊断信息，退出码为 2。执行或文件校验失败时退出码为 1，旧的 `current.json` 不会被失败结果替换。

## 查询排名和证据

```sql
SELECT
  rank,
  theme_code,
  theme_name,
  score,
  member_up_fraction,
  equal_weight_return,
  flow_strength,
  heat_strength,
  limit_up_breadth,
  board_strength,
  reason_consistency
FROM p02.main_ranking
ORDER BY rank
LIMIT 20;
```

查看一个主题为什么没有进入主榜：

```sql
SELECT
  theme_code,
  theme_name,
  effective_member_count,
  price_coverage,
  limit_coverage,
  reason_codes
FROM p02.price_diffusion
WHERE theme_code = ?;
```

查来源记录 ID：

```sql
SELECT source_record_id
FROM p02.evidence_link
WHERE theme_code = ?;
```

得到 ID 后，可以在统一参考库的相关 `accepted.<api>` 视图中查询 `source_record_id`，查看原字段、单位、观察时间和业务键。

## 结果该怎么理解

高分表示同一天内，主题的成员扩散、资金、注意力和涨停持续性相对靠前。分数不表示未来上涨概率，也没有给出买入价、仓位或自动下单信号。

小主题即使出现多只涨停，也会经过样本收缩。大主题成员多，涨停股数量应结合涨停广度看。跨来源共识能说明多个目录口径同时走强，但不同来源的成员定义仍然保留，不能把共识表当作唯一标准成分表。

## 当前正式验收基线

2026 年 10 月 14 日 release 已通过 `p02-validate`。最近 20 个交易日的行情、涨跌停、热度、资金和涨停事件全部认证，同花顺成员证书明确完成 1,666 个分区。

当前正式主榜有 385 个主题，价格扩散榜有 1,563 个主题，四来源独立分榜共 3,445 行，跨来源共识有 531 个主题。证据关系共 1,115,849 行。全部产品 Parquet 和轻量 DuckDB 合计约 20.7MB，统一参考库目录约 39MB，20 日新采输入约 91MB。

本次完整构建约一分钟，验证约 0.47 秒。单线程查询主榜前 20 行约 0.005 秒，按主题代码查一行约 0.003 秒，查询跨来源共识前 20 行约 0.003 秒。数字来自当前机器的一次验收，磁盘缓存和系统负载变化会影响耗时。
