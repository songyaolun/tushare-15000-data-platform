# 本地数据参考库使用说明

这套参考库给所有产品共用。采集、标准化和产品计算彼此分开，同一份行情、主题成员或财务数据不需要为每个产品再保存一遍。

## 一份数据分成四层

原始层保存 Tushare 成功响应。新批次使用确定性 gzip，文件名由公开请求和内容身份生成。重复请求得到相同内容时不会多写一份。Token 不进入文件、日志、异常、缓存键或 manifest。

标准层使用 ZSTD Parquet。每个采集批次都是不可变分片，字段中保留原字段、原单位、标准单位、观察时间、业务键和来源记录 ID。用于转换的 JSONL 是临时文件，Parquet 写完后立即删除。

目录层是轻量 DuckDB。`accepted.<api>` 和 `quarantine.<api>` 是读取 Parquet 的视图，DuckDB 不再复制整份明细。多个批次出现同一业务键时，`accepted` 只暴露观察时间最新的标准版本，旧版本仍留在不可变分片中。

产品层只保存结果字段和证据 ID。需要追溯时，再用证据 ID 回到参考库查询来源记录。这样能保留审计能力，也不会在结果、特征、门禁和血缘表里反复复制同一条来源数据。

## 目录里有什么

一个正式参考库通常包含这些文件：

```text
reference-root/
├── account.json
├── catalog.json
├── inventory.csv
├── quality-audit.json
├── reference.duckdb
└── datasets/
    └── <api>/
        ├── manifest.json
        ├── source_dictionary.json
        └── runs/
            └── <run-id>/
                ├── accepted.parquet
                ├── quarantine.parquet（有隔离记录时）
                ├── dictionary.json
                └── manifest.json
```

`raw/` 只出现在直接采集的库中。组合库不会复制原始页和 Parquet，它通过 manifest 引用已经校验过的来源分片。

## 范围证书说明这批数据到底覆盖了什么

每次完整采集都会生成范围证书，保存在 manifest 和 DuckDB 的 `scope_certificate` 表中。证书记录实际请求参数、请求分区数、成功分区数、返回的业务日期、质量状态和失败分区。

接口能调用不代表某个日期已经采全。结构校验通过也不代表产品可以发布。产品的 `ready` 状态必须逐项核对范围证书，不能只检查表是否存在。

查看某接口的证书：

```sql
SELECT
  api_name,
  status,
  observed_at,
  payload->'data_dates' AS data_dates,
  payload->'failed_partitions' AS failed_partitions
FROM scope_certificate
WHERE api_name = 'daily'
ORDER BY observed_at;
```

## 采集、离线重建和零复制组合

正式采集需要显式开启联网，并传入已有凭据文件。下面的参数文件可以给同一接口列出多个交易日或主题代码分区：

```bash
uv run tushare-hub \
  --db /path/to/hub.duckdb \
  reference build \
  --live \
  --credential-file /path/to/existing.env \
  --output /path/to/reference-batch \
  --parameters /path/to/parameters.json \
  --apis daily,stk_limit,ths_hot
```

规则、单位或字段映射更新后，可以只用原始页重建标准层，不再调用接口：

```bash
uv run tushare-hub reference rebuild \
  --output /path/to/reference-batch
```

多个批次可以组合成一个统一查询入口。组合过程不会复制 Parquet：

```bash
uv run tushare-hub reference compose \
  --source /path/to/static-reference \
  --source /path/to/market-reference \
  --source /path/to/theme-members-reference \
  --output /path/to/unified-reference
```

组合库保存来源文件的绝对路径和 SHA256。不要单独移动或修改被引用的来源目录。需要搬迁时，应连同来源目录一起搬，并重新执行 `reference compose`。

## SQL 和 Python 都可以直接读取

DuckDB 查询示例：

```sql
SELECT trade_date, count(*) AS securities
FROM accepted.daily
GROUP BY trade_date
ORDER BY trade_date DESC;
```

Python 示例：

```python
from pathlib import Path

import duckdb

reference = Path("/path/to/unified-reference/reference.duckdb")
with duckdb.connect(str(reference), read_only=True) as connection:
    rows = connection.execute(
        """
        SELECT ts_code, con_code
        FROM accepted.ths_member
        WHERE ts_code = ?
        ORDER BY con_code
        """,
        ["885800.TI"],
    ).fetchall()
```

正式查询使用单线程和 512MB 内存上限：

```python
duckdb.connect(
    str(reference),
    read_only=True,
    config={"threads": 1, "memory_limit": "512MB"},
)
```

## 失败时怎么处理

参数错误和权限错误不会盲目重试。网络超时、服务端临时错误和明确限流最多重试三次。分页重复、没有进展或达到页数上限都会把分区标成不完整。

新批次只有在分区完整、行质量通过、文件校验通过后才会进入活动 release。失败批次保留诊断记录，上一版活动 release 继续可用。

未授权接口不会被购买或伪装成已覆盖。P12 保持关闭，也不引入第二数据源核对 Tushare 数值。

## 当前主题成员批次的实测结果

2026 年 10 月 15 日完成的同花顺主题成员批次包含 1,666 个请求分区。所有分区均由供应商明确返回完整响应，共有 382,787 条合格成员记录，隔离记录为 0，业务键重复为 0。

目录中的 1,664 个主题返回了成员，2 个主题明确为空。1,591 个主题至少有 5 个成员，占非空主题约 95.6%。新标准层和轻量 DuckDB 共约 66MB；旧格式活动目录约 732MB。对全部 382,787 条成员执行 `count(*)` 的单线程实测约为 0.35 秒。具体耗时会随磁盘缓存和机器负载变化，因此性能验收应保留原始基准结果，不能把这一数字当作所有机器的保证。

统一参考库会额外生成 `reference-artifacts.json`。正常读取用数据库指纹、已认证 SHA256、文件大小和纳秒修改时间核对外部 Parquet，单次指纹检查实测约 0.04 秒。文件属性发生变化时才重算该分片的 SHA256。`reference compose` 仍会在接入来源时执行完整哈希校验。
