# 贡献指南

从 main 创建功能分支，提交使用 Conventional Commits。每次增加接口或改动字段契约时，同步更新政策、确定性 fixture、质量规则和消费映射。

每个函数的 docstring 描述功能、输入、输出及示例。每个测试说明场景与预期。默认测试完全离线，不接受真实账户响应或凭据作为 fixture。缺陷用例应证明业务约束，不能为了覆盖率删掉错误路径或使用排除标记。

提交前运行 `bash scripts/ci.sh`。门禁包括 Ruff、严格 mypy、pytest 与 100% 行覆盖率，以及离线 CLI 演示。100% 行覆盖不等于所有分支或所有市场场景已验证，新增边界仍需增加行为测试。

目录或政策的未知项必须显式保留债务。不要把默认字符串、空消费用途或未验证权限标记为完成。官方权益冲突应保留各自来源、原句和哈希；解决冲突时注明核验依据。

Codebase CI 配置位于 .codebase/pipelines/ci.yaml，以 Python 3.11 镜像运行同一验收脚本。仓库需要在平台启用 CI；本文档不代表已经配置平台准入规则。创建 MR 后检查平台是否识别并运行流水线，不自动合并或部署。
